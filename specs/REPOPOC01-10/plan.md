# Implementation Plan: FastAPI project skeleton with a health endpoint

**Branch**: `REPOPOC01-10-create-the-fastapi-project-skeleton-with` | **Date**: 2026-11-05 | **Spec**: `specs/REPOPOC01-10/spec.md`

**Input**: Feature specification from `specs/REPOPOC01-10/spec.md`

## Summary

Create a uv-managed Python 3.12 project with a FastAPI app under `app/`, one route `GET /health` returning `{"status": "ok", "version": "<app version>"}`, pytest tests under `tests/` using the FastAPI `TestClient`, and a README section on install, test and run. The version is defined once, as `__version__` in `app/__init__.py`. `pyproject.toml` reads it dynamically (hatchling `[tool.hatch.version]`), so project metadata and the `/health` response cannot differ (FR-002).

## Design Decisions

- **Single version source**: `app/__init__.py` has `__version__ = "0.1.0"`. `pyproject.toml` has `dynamic = ["version"]` and `[tool.hatch.version] path = "app/__init__.py"`. `app/main.py` imports `__version__` and returns it from `/health`.
- **Wheel layout**: `[tool.hatch.build.targets.wheel] packages = ["app"]` so `uv sync` can install the project.
- **Response model**: a small Pydantic `HealthResponse(status: str, version: str)` gives a documented, stable body. `status` is always `"ok"`.
- **Method handling**: only `@app.get("/health")` is registered, so FastAPI returns its standard 405 for other methods and 404 for unknown paths. No custom handlers.
- **Local start command**: `uv run uvicorn app.main:app --host 127.0.0.1 --port 8000`. The host is always explicit and the README never shows `0.0.0.0`.
- **Tests**: `tests/test_health.py` covers 200 and JSON body, the `status` and `version` fields, version equal to `app.__version__` and to the installed package metadata, 405 for POST, and 404 for an unknown path.
- **Research/data-model/contracts**: no unknowns remain and there are no entities. The only contract is the `/health` response shape in the spec (FR-001), so no extra design files are created.

## Risks

1. **Packaging and dynamic version**: a wrong hatch config breaks `uv sync` or leaves metadata stale. Mitigation: a test compares `importlib.metadata.version` with `__version__`, and the task verifies a clean `uv sync`.
2. **`uv.lock` and Python 3.12 availability** in the agent or CI environment. Mitigation: commit `uv.lock` and pin `.python-version`.
3. **ruff on the whole repo**: `uvx ruff check .` also scans `specs/` and other folders; keep Python files lint-clean and configure ruff only in `pyproject.toml` (`[tool.ruff]`), without adding it as a dependency.
